# تحليل فجوة Observation Workspace — تغذية تنفيذية لـ#143

## 1. الصفحات الحالية

| Route | المكوّن | الدور في الرحلة الحالية |
| --- | --- | --- |
| `/notes`, `/notes/workspace` | `ObservationWorkspacePage` | نقطة الدخول الرئيسية — قائمة+تفاصيل (Master-detail حقيقي) |
| `/notes/new` | `NoteCreatePage` | إنشاء (صفحة كاملة منفصلة) |
| `/notes/:id` | `NoteDetailPage` | تفاصيل كاملة + كل الإجراءات غير المضمَّنة في Workspace |
| `/notes/:id/edit` | `NoteEditPage` | تعديل الحقول (صفحة كاملة) |
| `/notes/:noteId/corrective-actions/new` | `CorrectiveActionCreatePage` | إنشاء إجراء تصحيحي من ملاحظة |
| `/corrective-actions` | `CorrectiveActionsListPage` | قائمة شاملة عابرة للملاحظات (تدعم فلتر `noteId`) |
| `/corrective-actions/:id` | `CorrectiveActionDetailPage` | إدارة إجراء تصحيحي كاملة |
| `/corrective-actions/:id/edit` | `CorrectiveActionEditPage` | تعديل إجراء |
| `/settings/escalations*` (4 صفحات) | Escalation pages | إدارة سياسات وعرض حوادث التصعيد — منفصلة تمامًا عن أي إجراء لحظي على ملاحظة |
| `/attachments` | `AttachmentsPage` | رفع عام غير مرتبط بملاحظة تحديدًا |
| `pages/notes/NotesListPage.tsx` | — | **يتيمة، غير موجَّهة، تحتوي وظيفة استعادة أرشيف فريدة** |

## 2. الوظائف المتكررة

- شريط بحث+فلاتر (منطقة/سجن/حالة/خطورة) مكرَّر بين `ObservationWorkspacePage` و`NotesListPage` اليتيمة، بتنفيذين منفصلين تمامًا.
- عرض مرفقات مكرَّر بثلاث قدرات مختلفة: رفع+قائمة (`NoteDetailPage`)، قائمة فقط (`CorrectiveActionDetailPage`)، عرض فقط بلا حتى تنزيل مؤكَّد (`ObservationWorkspacePage`'s attachments tab).
- عرض تاريخ/سجل الحالة مكرَّر بين تبويب "السجل الزمني" في Workspace و`api.notes.history` المُستدعى مباشرة في `NoteDetailPage`.

## 3. الإجراءات التي تتطلب مغادرة Workspace

| الإجراء | لماذا يغادر اليوم |
| --- | --- |
| إنشاء ملاحظة | لا نموذج مضمَّن؛ ينتقل لـ`/notes/new` |
| تكليف/إعادة تكليف (ASSIGN/REASSIGN) | لا نموذج تكليف مضمَّن؛ خارج `INLINE_ACTIONS` |
| اعتماد إغلاق (`verifyClosure`) | خارج `INLINE_ACTIONS` |
| إضافة إجراء تصحيحي | ينتقل لصفحة إنشاء منفصلة (منطقي جزئيًا لأنه كيان مستقل، لكن الإدارة الكاملة بعدها تفارق الملاحظة تمامًا) |
| رفع مرفق | تبويب المرفقات في Workspace قراءة فقط |
| التصعيد اليدوي لعنصر بعينه | غير موجود إطلاقًا في أي مكان، ناهيك عن كونه داخل أو خارج Workspace |

## 4. الشاشات المرشَّحة للدمج/الإلغاء/البقاء كـAdvanced Fallback

| الشاشة | القرار المستهدف | السبب |
| --- | --- | --- |
| `NoteCreatePage` | Merge into Workspace | نموذج إنشاء مضمَّن يرث `facilityId` من سياق الدخول |
| `NoteDetailPage` | Merge into Workspace | كل محتواه يجب أن يصبح متاحًا داخل Split View/Panel |
| `NoteEditPage` | Merge into Workspace | تعديل مضمَّن بدل صفحة منفصلة |
| `CorrectiveActionCreatePage` | Merge into Workspace | نموذج مضمَّن ضمن سياق الملاحظة |
| `CorrectiveActionDetailPage` | Merge into Workspace (كـPanel من داخل الملاحظة) | مع الإبقاء على إمكانية الوصول المباشر عبر `/corrective-actions/:id` كرابط دائم (Deep link) وليس كصفحة تصفح أساسية |
| `CorrectiveActionsListPage` | **Advanced fallback** | قيمة مستقلة حقيقية كقائمة شاملة عابرة للملاحظات (متابعة تحميل عمل الفرق) — تبقى موجودة لكن ليست المسار الأساسي |
| `NotesListPage` (اليتيمة) | Remove — **بشرط نقل قدرة استعادة الأرشيف أولاً** إلى Workspace الجديد أو صفحة إعدادات مناسبة | وظيفتها الأساسية superseded بالكامل، ووظيفتها الفريدة يجب ألا تُفقَد |
| صفحات التصعيد الأربع | Advanced fallback | إدارة سياسات مهمة تقنيًا لكنها ليست تشغيلاً يوميًا لكل الأدوار |
| `AttachmentsPage` | Advanced fallback | يبقى كرفع عام غير مرتبط بملاحظة، بعد إضافة رفع مباشر داخل كل سياق (ملاحظة/إجراء) |

## 5. العقود التي تحتاج Consolidation دون كسر Backend

- **`api.notes.workspaceDetail`** موجود بالفعل ويحمل `AllowedActions` — هذا هو العقد الصحيح للبناء عليه لكل من القائمة والتفاصيل الموحّدة؛ لا حاجة لعقد جديد.
- **`api.notes.attachments`/`uploadAttachment`** يجب استدعاؤهما من نفس اللوحة الموحَّدة بدل تكرارهما بقدرات متفاوتة عبر 3 مكونات.
- **الإجراءات التصحيحية**: `CorrectiveActionDetailDto` لا يحمل `AllowedActions` (فجوة موثَّقة في تدقيق العقود الخلفية) — يُنصَح بإضافته على غرار الملاحظات قبل أو أثناء دمجها داخل Workspace، بدل استمرار اشتقاق الإجراءات المسموحة يدويًا في العميل.
- **التصعيد**: لا عقد "صعّد هذا العنصر الآن" موجود من الأساس — أي إجراء تصعيد يدوي مباشر يحتاج Endpoint جديد (نطاقه خارج هذا التدقيق، يُذكر كفجوة Backend يجب تقييمها ضمن تنفيذ #143).

## Target Flow — Observation Workspace المستهدفة (وليس مجرد ملاحظات)

**مساحة تشغيلية واحدة (`/notes/workspace` كمسار وحيد، مع إزالة تكرار `/notes`)** بنمط Master-detail/Command Workspace:

1. **قائمة الملاحظات** (اللوحة اليسرى الحالية تبقى) — بحث+فلاتر محفوظة في الرابط (موجودة فعليًا، تُحافَظ عليها).
2. **لوحة التفاصيل** تعرض: الملخص (حالة/خطورة/مهلة/مالك)، **الإجراء التالي المقترح** بناءً على `AllowedActions` الفعلية من الخادم (وليس افتراضًا في العميل).
3. **نموذج إنشاء ملاحظة مضمَّن** (Slide-over أو قسم داخل نفس الصفحة) يرث `facilityId` من سياق الدخول عند القدوم من Facility Workspace، ومن اختيار صريح عند القدوم من الشريط العام.
4. **نموذج تكليف/إعادة تكليف مضمَّن** بدل التنقّل الكامل.
5. **قسم الإجراءات التصحيحية** ضمن نفس اللوحة: إنشاء، إسناد، متابعة — مع رابط دائم مستقل (`/corrective-actions/:id`) يبقى صالحًا لمن يصل إليه مباشرة من إشعار أو بحث خارجي.
6. **قسم التصعيد**: عرض تاريخ التصعيد الفعلي لهذه الملاحظة (إن وُجد) + إجراء "صعّد الآن" (يتطلب Endpoint جديد).
7. **قسم المرفقات الموحَّد**: رفع+قائمة+تنزيل من نفس المكان، بنفس القدرات، بغض النظر عن كون العنصر ملاحظة أو إجراء تصحيحي.
8. **قسم المراجعة والتحقق والإغلاق وإعادة الفتح**: كل الإجراءات (بما فيها `verifyClosure`) مضمَّنة عبر `AllowedActions`، لا حجب أي إجراء خارج قائمة ثابتة في العميل (`INLINE_ACTIONS` يجب أن تصبح مشتقة من الخادم لا Set ثابتًا في الكود).
9. **سجل زمني موحَّد** يجمع: تغييرات الحالة، التكليفات، الإجراءات التصحيحية، المرفقات، التصعيد — في تسلسل واحد بدل تبويبات منفصلة متفرقة.
10. **العناصر المرتبطة**: روابط لأي كيان آخر (خطر، عهدة، مورد) إن وُجد ارتباط فعلي مسجَّل.
11. **فتح العنصر التالي دون الرجوع للقائمة**: زر "التالي"/"السابق" صريح يعمل على نتيجة الفلتر الحالية.
12. **مسار الاستعادة الأرشيفية** (منقول من `NotesListPage` اليتيمة) يصبح إجراءً متاحًا ضمن صلاحية `Notes.Restore` من نفس اللوحة أو من شاشة إعدادات مخصصة، وليس مفقودًا بحذف الملف.

# Phase D.6 — تحليل الوضع الحالي قبل بناء سجل المخاطر المؤسسي

تاريخ المراجعة: 2026-07-27. يغطي هذا المستند مراجعة الكود الفعلي (Domain، Application، Frontend) قبل أي تصميم أو Migration، طبقًا لمتطلبات Phase D.6.

## الخلاصة

لا يوجد أي نموذج Domain قائم لإدارة المخاطر. الكود يعترف صراحة بهذه الفجوة:
`Baseera.Application/Workspaces/FacilityWorkspaceReadService.cs:329` يعرّف:

```csharp
MissingDomain("risks", "المخاطر والمعالجات", "لا يوجد Risk/RiskTreatment engine في النطاق الحالي.", "#16"),
```

وفي الواجهة، `src/frontend/src/pages/workspaces/FacilityWorkspacePage.tsx` يعرض هذا الفجوة عبر `DomainUnavailableSection` لقسم `'risks'` مع `followUpIssue: '#16'`. هذا التحليل يؤكد عدم وجود نموذج مواز يمكن الخلط معه، مع تحديد الأنماط الواجب إعادة استخدامها بدل ابتكار أنماط جديدة.

## القرار النهائي

لا يوجد نموذج مخاطر قابل لإعادة الاستخدام مباشرة — البناء من الصفر داخل `Baseera.Domain.RiskManagement` مبرر وآمن. جميع الأنماط الهيكلية (القاعدة، النطاق، دورة الحياة، التدقيق، الاستيراد، المرفقات، لوحة العمل) لها قوالب ناضجة في الكود الحالي ويجب اتباعها حرفيًا بدل ابتكار أنماط بديلة، وهو ما اعتمده تصميم هذه المرحلة بالكامل (انظر `docs/phase-d6-risk-domain-model.md`).
